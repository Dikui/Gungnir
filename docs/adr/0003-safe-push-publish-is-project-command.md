# safe-push 只执行项目声明的发布命令，不内置具体发布渠道

为了让多台设备上的 DSH 检测到自开发插件的更新，每次发版要在插件索引中登记新版本和推送后的提交号。safe-push 为此只提供两个通用、可选的推送规则声明：“推送后发布”（推送并核实远端后，把 `{version}`、`{sha}` 代入项目声明的命令执行）和“必须提交的构建产物”（提交前运行构建，产物视为核心内容）。索引格式、地址转换、校验和索引仓库推送都由项目自己的发布命令负责。原因有两点：safe-push 是给各种代理和项目用的公开通用技能，大多数项目与 DSH 无关；私人工具也不放进本仓库。

**Considered Options**：把 DSH 索引的写入和校验直接写进 safe-push。未采纳：这会把一个特定渠道的格式和私人索引仓库绑进通用技能，DSH 格式变化时还得给 Gungnir 发版。改发 npm、由设备按包名检测更新。未采纳：用户选择不维护 npm 发布，改用 DSH 0.2.3-alpha.1 起支持的 Git 索引源。
