## 它会做什么

`ask-dikui` 根据当前任务推荐技能和使用顺序，帮助你确定下一步。输入可以是一个想法、积压的外部缺陷报告或功能请求、难以规划的大任务，或阶段结束后的上下文取舍。

它按本仓库定义的流程说明分支条件，只推荐技能，由你调用所选技能。建议既包括下一步做什么，也包括哪些地方需要你作决定、何时保留或清空上下文。

## 什么时候使用

当你不知道该从哪个技能开始，或不清楚两个相近技能的分工时使用。由你输入 `/ask-dikui` 调用，代理判断适用时也会自行调用。

已有项目目录时，通常从 `/grill-with-docs` 开始；没有可记录的目录时，用 `/grill-me`。范围明确的功能按规模进入实施；一次会话无法规划清楚的大任务，先用 `/wayfinder` 建立决策地图。

## 这是对话，需要你做决定

你描述任务处境，再根据推荐选择技能。一次会话能完成时可用 `/implement`；需要多次会话时，先用 `/to-spec` 整理需求，再用 `/to-tickets` 拆任务，选择逐项实施或用 `/implement-spec` 按依赖并行实施。

访谈到拆任务保留同一上下文，不在中途清空或压缩；接近上下文可用范围时，在最近的阶段结束处压缩。每个独立实现任务使用新会话。需要复盘时，在清空前使用 `/retro`，或提供原会话日志。

阶段结束后，按以下顺序判断，第一个适用的选项优先：

| 选项 | 何时选择 |
| --- | --- |
| 继续当前会话 | 下一阶段需要当前讨论，或上下文仍有足够空间 |
| `/clear` | 当前上下文对下一步已无用 |
| `/handoff` | 更换运行环境、目录或协作者，或分出旁支任务 |
| 子代理 | 任务范围明确，可以独立完成并返回报告 |
| `/compact` | 以上都不适用，需要用摘要继续 |

## 如何判断它有效

- 推荐对应你的任务处境，并说明选择依据。
- 区分一次会话可完成的工作与需要需求、任务拆分的工作。
- 说明哪些步骤需要你选择，以及如何处理上下文。
- 推荐结束后由你调用技能，代理没有代替你启动所推荐的流程。

## 常见问题

**所有任务都要经过同一套流程吗？**

不需要。外部缺陷报告或功能请求先用 `/triage`，难以定位的缺陷先用 `/diagnosing-bugs`；需要查事实或做验证时，可单独用 `/research` 或 `/prototype`。自己拆出的任务不必再交给 `/triage`。

**它能代替具体技能的说明吗？**

不能。这里提供选择路线，具体执行条件以对应的 `SKILL.md` 为准。例如 `/wayfinder` 默认先解决决策，路径明确后再整理需求；只有任务很小时才直接实施。

## 它在工作流中的位置

它是选择入口。首次使用工程流程前，先用 `/setup-dikui-skills` 配置任务存放位置和领域文档入口。选定技能后直接调用；调用层级见[调用规则](../invocation.md)。
