## 它会做什么

`research` 启动后台代理，基于一手来源调研问题，把结论及每项结论的引用写入仓库中的 Markdown 文件。你可以在它阅读时继续工作。

来源限于官方文档、源码、规范和官方 API，不使用二手解读。结果优先保存在仓库已有的笔记目录；没有约定时，代理选择合理位置并说明路径。

## 什么时候使用

当一个问题需要查证文档、接口行为或源码，而你希望把阅读交给后台代理并保留可查阅的结果时，输入 `/research` 并说明要回答的问题。

可直接调用，也会被 `/wayfinder` 等技能加载。代理不会根据普通对话内容自行加载。

尽量提供具体对象和范围，例如某个 API 在指定版本下的行为。需要通过实物验证行为是否可行时，可由你调用 `/prototype`；需要共同作出设计决策时，可用 `/grill-with-docs` 讨论调研结果。

## 如何判断它有效

- 调研交给后台代理处理，主会话可以继续工作。
- 每项结论都有对应事实来源，引用指向官方材料、规范或实际源码。
- 结果写成 Markdown 文件，保存位置遵循仓库笔记约定，或已说明所选路径。
- 文件回答了你提出的问题，可以带入后续讨论供人核对。

## 常见问题

**它会替你作出决策吗？**

它的职责是带回有引用的调研结论。你可以据此继续访谈、规划或设计，重要决策仍需在对应流程中讨论和记录。

**它有固定停止标准或禁止嵌套委派的规则吗？**

当前技能没有规定搜索次数、时长或停止标准，也没有限制后台代理再次委派。调用时明确问题和范围，有助于检查结果是否回答了真正需要查证的事项。

**结果会自动成为后续会话的上下文吗？**

本技能负责写出文件，没有规定自动加载旧结果或自动归档。需要复用时，把文件路径提供给后续会话；是否保留或提交，按项目约定决定。

## 它在工作流中的位置

调研为决策提供事实依据。你可以把结果带回 `/grill-with-docs` 讨论，或交给 `/to-spec` 整理需求；`/wayfinder` 则会加载本技能，处理决策地图中的调研任务。
