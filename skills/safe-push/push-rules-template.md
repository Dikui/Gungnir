# 项目推送规则

可选，手动创建 `docs/agents/push-rules.md`。自然语言部分供代理判断，默认不执行其中的命令。

- 仓库公开性：待确认。
- 受保护分支：按仓库说明及用户确认填写。
- 允许推送的 remote 与目标分支：填写名称和不含凭据的 URL。
- 提交约定：根据已有提交填写。
- 测试假数据目录及来源：填写实际目录，不默认豁免。
- 内部代号、内网或工单链接、未公开计划的资料入口：填写实际位置。

## 版本文件

按项目实际结构填写本项目自身版本的路径和字段。例如：

- `package.json` 的 `version`。
- `package-lock.json` 的顶层 `version` 和 `packages[""]` 中的 `version`，仅本包自身的两处，不含依赖条目。
- `.claude-plugin/plugin.json` 的 `version`（项目使用该文件时）。

只修改这里列出的本项目自身版本字段；未列出的文件（如 CHANGELOG、历史说明）不改。没有版本文件时写明未找到。

## 推送后发布

可选。仅在当前分支和推送目标都是默认分支，且推送成功并核实远端引用后，safe-push 才在仓库根目录执行本节声明的命令。本节是自然语言部分不自动执行命令的例外。

- 填写一条可安全重复执行的发布命令。可用 `{version}` 表示本次版本号，`{sha}` 表示已推送提交的完整 40 位小写 SHA。
- 填写命令会推送到的仓库（路径或不含凭据的 remote URL）和目标分支。

## 限定豁免

下块每行 `路径glob ERE正则`。路径不能含空白，必须含 `/`，例如 `tests/fixtures/*`；`*` 匹配任意字符（含 `/`），`?` 匹配单字符，其余字符按字面匹配。正则与路径须同时匹配才豁免。正则匹配新增行、文件名或属性说明；不能只写一项，也不能用 `*` 或 `**` 作全局路径。不要用 `.*` 无差别放行目录内全部内容。密钥豁免仅用于已核实的假数据。

```safe-push-allow
# tests/fixtures/* <限定假数据内容的ERE>
```

块标记必须独占一行并从行首开始。块内空行和以 `#` 开始的行是注释。非法行或非法 ERE 导致扫描错误（退出码 2）。
