# 局部测试

一次实现完成后运行。只测试这次改动影响的范围，不运行完整测试套件；完整测试套件由 CI 或用户运行。

探索代码前，读取已有的 `GLOSSARY.md` 和相关 ADR。测试名使用领域词汇。

## 1. 确定范围

读取这次改动的 diff。调用方给出基准时用该基准；没有时用当前分支相对主分支的差异。列出改动的模块、函数和对外行为，以及覆盖它们的现有测试。

用项目已有的过滤方式只运行这些测试，例如 `ctest -R`、`ctest -L`、`--gtest_filter`、`pytest <文件>::<测试>`、`go test -run`。

完成条件：已列出受影响项、对应测试和运行命令。

## 2. 补测试

受影响项没有测试覆盖时，为它构造测试：

- 测试走公开接口。要测的函数没有可用的公开接口时，先把它抽成可以单独测试的小组件；不用 `FRIEND_TEST`，也不测私有方法。
- 测试数据默认在测试代码中构造。构造参数多到淹没断言时，写带默认值的 builder，测试只改它关心的字段。
- 只有三类数据存成文件：要人审 diff 的期望输出、二进制或超大样本、必须原样保留的输入。数据文件放在用到它的测试旁边。
- 测试数据只用合成数据，不用真实用户数据。
- 改动涉及状态机时，写一个更简单的模型（如转移表），检查每个操作后实现的结果与模型一致，并检查不变量。只检查状态合法不够。

完成条件：每个受影响项都有测试覆盖，或已写明不能测试的原因。

## 3. 运行

运行第 1 步的命令和第 2 步新增的测试。测试失败时，判断是代码错误还是测试错误，修复后重跑。

完成条件：全部通过；或已报告未通过的测试、失败输出和判断。

## 4. 筛选

逐条检查这次新增或修改的测试。四个问题都答“是”才保留：

1. 测试名是否读成一条可观察的契约？需要用“和”连接时，拆成两条。
2. 行为改变时，它会失败吗？
3. 只做重构、行为不变时，它仍通过吗？
4. 它失败时，能否直接看出哪条契约被破坏？

以下测试在验证后删除：

- 只为接通对象或假依赖而写的脚手架。
- 断言调用顺序、私有状态或内部格式的测试。只有交互本身是契约时（如“这条路径不得访问网络”）才保留。
- 没有断言或吞掉异常的测试。
- 与已保留的测试在同一契约、同一类输入上重复的断言。
- 性质测试生成的随机执行路径。只保留缩小后的反例。

已有测试不能仅因“这次没运行到”或“行覆盖与其他测试重复”而删除。

完成条件：每条新增或修改的测试都已标为保留或删除，标为删除的已删除。

## 5. 写入项目

保留的测试按下表放置。项目已有测试约定时，沿用项目约定。

| 类型 | 位置 |
| --- | --- |
| 单元测试、性质测试 | 按模块一个测试文件，默认 `tests/<模块>/<名称>_test.<扩展名>`，文件中可有多个测试。同一行为的多组输入写成表驱动或参数化测试 |
| 场景和回归用例：断言整份输出（诊断、生成结果、协议、SQL 结果等） | 一个用例一个文件，默认 `tests/cases/<功能>/<用例>.<扩展名>`。输入和期望写在同一文件，或放成同名的期望文件；多文件场景打包成一个文件 |

场景用例需要一个按目录发现用例的 runner。项目没有时，第一次沉淀场景用例时编写它，并加入项目的测试命令。期望输出文件只能通过显式命令更新，更新前先读 diff。

每条保留的测试记录元数据：

- 测试名写成契约。
- 用项目的标签机制（如 CTest `LABELS`、pytest marker）标出规模（`small`、`medium`、`large`）和种类：`spec`（契约）、`regression`（来自真实缺陷）、`property`（性质或模型）、`pin`（记录现有行为，待确认后改为 `spec` 或删除）。
- 在测试旁用注释写来源：缺陷编号、任务单编号或 ADR 编号。场景用例在文件开头用一两句说明它保护的行为和来源。
- 使用假依赖时，用注释写明它替代了什么。

C++ 项目中，一个库对应一个测试可执行文件，用 `gtest_discover_tests` 登记到 CTest。不为每个用例建一个可执行文件。

完成条件：保留的测试都在上表位置并带元数据；项目的测试命令能运行它们。

## 6. 清理过时测试

这次改动取代了某个 ADR、修改了某条契约或删除了代码时，按来源编号和编译错误找出相关测试：

- 契约改变的测试，更新期望。
- 对应代码已删除的测试，删除。
- 契约没有改变却失败的测试，改写为测试公开接口，或删除。不机械地修改期望值。

完成条件：已按来源编号搜索；找到的测试已更新或删除，或已写明没有找到。

## 报告

列出运行的命令和结果、保留的测试及位置、删除的测试及原因、未覆盖的受影响项。本轮没有运行过的检查，不说通过。
