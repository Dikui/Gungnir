# 项目推送规则

由代理先探索仓库并展示此文件的完整草稿，用户确认后写入 `docs/agents/push-rules.md`。

- 仓库公开性：待确认。
- 默认分支与受保护分支：按 remote 默认引用、仓库说明及用户确认填写。
- 允许推送的 remote 与目标分支：填写名称和不含凭据的 URL。
- 提交约定：根据已有提交填写。
- 测试假数据目录及来源：填写实际目录，不默认豁免。
- 内部代号、内网或工单链接、未公开计划的资料入口：填写实际位置。

## 版本文件

按项目实际结构填写本项目自身版本的路径和字段，由用户确认。例如：

- `package.json` 的 `version`。
- `package-lock.json` 的顶层 `version` 和 `packages[""]` 中的 `version`，仅本包自身的两处，不含依赖条目。
- `.claude-plugin/plugin.json` 的 `version`（项目使用该文件时）。

只修改这里列出的本项目自身版本字段；未列出的文件（如 CHANGELOG、历史说明）不改。没有版本文件时写明未找到；后续推送仍询问是否指定版本文件或本次不升版本。

## 追加与调整

下块每行 `block|warn 类别编号 ERE正则`，正则可含空格，无引号包裹。匹配新增行、文件名或属性说明时，追加命中并调整同类别命中的级别；后匹配的规则优先。第 1 类只接受 `block`，降级会被忽略并提示。第 12 类中的密钥同样不能降级。

```safe-push-deny
# 按项目发现填写；不写真实凭据或看起来像凭据的示例。
```

## 限定豁免

下块每行 `路径glob ERE正则`。路径不能含空白，必须含 `/`，例如 `tests/fixtures/*`；`*` 匹配任意字符（含 `/`），`?` 匹配单字符，其余字符按字面匹配。正则与路径须同时匹配才豁免。正则匹配新增行、文件名或属性说明；不能只写一项，也不能用 `*` 或 `**` 作全局路径。不要用 `.*` 无差别放行目录内全部内容。密钥豁免仅用于已核实的假数据。

```safe-push-allow
# tests/fixtures/* <限定假数据内容的ERE>
```

块标记必须独占一行并从行首开始。块内空行和以 `#` 开始的行是注释。非法行或非法 ERE 导致扫描错误（退出码 2）；第 1 类降级除外，忽略并继续。自然语言部分供代理判断，不自动执行其中的命令。
