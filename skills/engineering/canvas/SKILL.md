# Canvas

维护一张供设计、开发、测试和验收复用的产品框架图。用户可显式调用本技能来创建、修改或导出图。它与 wayfinder 独立，不自动调用其他技能。

## 打开项目

使用完整插件附带的 Canvas MCP，用户无需手动启动服务。

1. 从当前请求及用户提供的需求、边界和测试场景开始。沿项目 `AGENTS.md` / `CLAUDE.md`、`docs/agents/domain.md` 的入口，按需读取已有框架图、领域词汇、ADR、spec、代码和测试。保留文件或 issue 引用，不要求补齐整套文档。
2. 从项目文档入口确定结构图路径。调用 `canvas_open_project`，传入当前项目的绝对 `projectPath` 和已登记的 `architecturePath`，默认路径为 `docs/architecture.md`。路径必须在项目内，不得使用插件安装目录。
3. 服务自动启动，返回 `canvasId`、项目文件路径和浏览器 URL。打开该 URL 供协同编辑。后续工具调用都使用此 `canvasId`，避免混用其他项目的画布。

已有 Markdown 会自动加载为可编辑图，无需再次导入。文件不存在时打开空画布，不加载演示内容。位置、样式和未同步草稿缓存在本机，插件升级不会覆盖项目 Markdown。

工具缺失时，说明需要安装带 MCP 的完整插件，不能只复制技能。启动失败时报告实际错误，不声称已打开，也不擅自修改客户端全局配置。

## 读取画布

调用 `canvas_get_context` 判断是否为空画布。默认返回完整 `nodes`、`edges`、方向、文字、来源、项目说明、最新 revision 和选区，不返回布局、样式和事务历史。只在调整布局时传入 `geometry: true`。

`canvas_read_architecture` 返回完整项目 Markdown，包括保留的人工说明和来源。选择一种表示来理解当前图，避免同时读取两种完整表示。选区只表示关注范围，不授权删除或替换其他内容。

## 创建或修改

### 创建初版

从输入中提取主要模块、职责、连接方向和交互说明，用测试场景理解关键路径。只画当前范围，未确定的设计写明“待确认”。绘图不表示测试已通过，也不能把所有模块默认标为已实现。

构造 Mermaid `flowchart`，通过 `canvas_import_markdown` 加入画布。只使用矩形节点和带文字的连线；工具不支持 subgraph、非矩形节点、样式指令或多个图块。

### 修改已有图

使用 `canvas_apply_patch` 修改相关节点和连线，保留用户已确定的模块、方向、描述及无关内容。使用 `canvas_get_context` 返回的真实图形 ID。Markdown 模块标识只用于保存和恢复文档关联，不能直接用于编辑画布。

导入会追加内容并产生副本。只有从 Markdown 恢复画布中尚不存在的图时，才使用导入工具。

每次完整调整使用一个带 `baseRevision` 的事务。版本冲突时，重新读取内容并判断改动，不能只更新 revision 后重放旧操作。撤销时，用当前 revision 和该事务 ID 调用 `canvas_undo`；对象已有后续编辑时，不强行覆盖。

### 整理布局与核对结果

创建、删除、连接模块的事务，以及导入完成后，会自动整理全图。整理可移动或调整全图几何，但保留模块、连接对象、方向和文字。文字编辑和人工拖动不触发整理。

单独整理时，调用 `canvas_arrange` 并传入最新 `baseRevision`，无需逐个计算或提交坐标。整理结果可按事务撤销。用结构化几何判断布局，不增加截图或图像识别流程。

每轮修改前重新读取最新画布。修改回执只返回 revision、transactionId、changedIds 和草稿状态，不重复返回全图或历史。根据回执判断是否成功，仅在需要继续读取内容时获取框架。

整理回执和几何上下文中的布局提示会指出相关对象；直线与标签遮挡只是几何估计。界面的直接关系、上下游和有向路径聚焦只是临时查看状态，不改变底图，也不代表真实代码影响或测试覆盖。

## 保留状态和来源

导出包含全部方框描述、连接方向、连线描述和来源，并保留项目 Markdown 中的人工说明。

“待确认”“设计已确认”“已实现”等状态应写入方框、连线文字或文档说明，不能只依赖颜色、便签或元数据。状态须有用户确认或项目证据支持。决策理由和详细需求保留在原文档中。

用模块的 `refs` 保存单行文件引用或 HTTP(S) 链接。可通过创建、更新模块的 patch 或界面编辑。只保存引用，不复制原文；有引用不表示已核验内容。

来源随同一 Markdown 的 `canvas:references` 小节保存和恢复。不要手工更换模块标识，也不要把来源只存入本机草稿。

## 结束前保存

每次正常结束前，自动更新项目结构图。即使本轮只有人工编辑或讨论，也必须保存，无需用户另行要求同步。

1. 确认本轮浏览器编辑已保存为服务端草稿，调用 `canvas_get_context` 获取最新 revision。
2. 调用 `canvas_save_project`，传入对应 `canvasId` 和 `baseRevision`。工具将最新画布写入登记的项目 Markdown，保留图块前后的人工说明，并回读验证。不得用早先的导出结果或 shell 覆盖文件。
3. 成功后给出结构图路径和同步结果，再按下一节登记文档入口。

revision 过期时，重新读取再保存。项目 Markdown 被外部修改、图语法不支持或导出失败时，保留文件和草稿，说明未同步的原因，不自动覆盖或丢弃任一方。

重新打开时，未修改的画布可加载外部更新。如果存在未同步草稿且文件也已变化，先处理冲突。

`canvas_read_architecture` 只用于读取或导出副本，不写项目文件。界面的“保存到项目”与 `canvas_save_project` 使用同一流程。本次结束后发生的编辑，在下次调用时同步，不提供后台 Markdown 同步。

## 登记文档入口

首次成功保存后登记入口，之后仅在路径变化时更新，保留周围内容：

- 已有 `docs/agents/domain.md`：写入框架图的实际相对链接和适用场景，并确保项目规则文件有指向该文档的入口。
- 没有该文档：直接在现有 `AGENTS.md` / `CLAUDE.md` 中登记，无需运行初始化技能。沿用项目约定；两者都存在时只写一处，都不存在时创建 `AGENTS.md`。

在 `docs/agents/domain.md` 中登记的示例：

> 产品框架图：[architecture.md](../architecture.md)，由 Canvas 导出。分析模块职责、交互关系、核心流程或结构变更时，按需读取此图，并结合相关需求、ADR、代码和测试。它是设计参考，不表示所有内容均已实现。

## 后续使用

框架图长期保留，用户可在任何阶段调整。后续设计可按需直接读取完整 Markdown，无需启动 Canvas 或读取本技能；读取文档不构成调用技能的授权。

读取时完整保留模块、关系、描述、状态、约束、待确认事项和来源，不擅自摘要、截断或只返回局部图。仅在当前问题需要时展开来源原文。

不增加持续检查、固定审查时点或所有技能必读要求。设计冲突沿用当前任务的分析和反馈流程；图与代码不同时，不自动认定哪一方错误。
