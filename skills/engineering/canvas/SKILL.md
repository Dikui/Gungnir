# Canvas

维护一张跨设计、开发、测试和验收阶段复用的产品框架图。用户可以显式调用本 skill 生成初版、修改现有图或导出当前图；它不是 wayfinder 的必经前置步骤，也不自动调用其他 skills。

## 接入与输入

通过随插件安装的 Canvas MCP 工作，无需用户手动启动画布服务。先调用 `canvas_open_project`，传入当前工作项目的绝对 `projectPath`，以及已登记的 `architecturePath`（默认 `docs/architecture.md`）；不要把插件安装目录当成项目。服务自动启动并返回 `canvasId`、项目文件路径和浏览器 URL。打开该 URL 供协同编辑，后续所有 Canvas 工具都携带对应的 `canvasId`，不要混用其他项目的画布。

如果工具缺失，说明需要安装带 MCP 的完整插件，而不是只复制 skill。若启动失败，报告实际错误，不声称已打开画布；不要擅自修改客户端全局配置。

从当前请求及用户提供的需求、边界和测试场景开始。沿项目 `AGENTS.md` / `CLAUDE.md`、`docs/agents/domain.md` 中的入口，按当前问题读取已有框架图、相关领域词汇、ADR、spec、代码和测试。保留文件或 issue 引用，不要求先补齐整套文档。

先沿项目文档入口确定结构图路径，再打开项目画布。已有 Markdown 会自动加载成可编辑图；文件不存在时是空画布，不加载演示内容，也不重复导入已加载的图。路径必须位于项目内。位置、样式和未同步草稿缓存在本机，插件升级不会覆盖项目 Markdown。

## 生成或协同修改

1. 打开项目后，用 `canvas_get_context` 判断是否为空画布。默认返回完整 `nodes`、`edges`、方向、文字、来源引用、项目说明、最新 revision 和选区，不附带布局、样式或事务历史；只有调整布局时才传 `geometry: true`。`canvas_read_architecture` 返回完整项目 Markdown，包括保留的人工说明和来源。不要同时读取两种完整表示来重复理解同一张图。选区只表示关注范围，不能据此假定用户要删除或替换其余内容。
2. **初版图**：根据输入提取主要模块、职责、连接方向和交互说明，用测试场景帮助理解关键路径。只画当前范围，有待确认的设计写明“待确认”。不把所有模块默认标为已实现，也不把绘图当成测试已通过。构造一个 Mermaid `flowchart`，使用矩形节点和带文字的连线，通过 `canvas_import_markdown` 加入画布。该工具只支持受限 Mermaid 子集：不使用 subgraph、非矩形节点、样式指令或多个图块。
3. **已有图**：通过 `canvas_apply_patch` 修改相关节点和连线，保留用户确定的模块、连接方向、描述及无关内容。使用 `canvas_get_context` 返回的真实图形 ID；Markdown 中的模块标识用于保存和恢复文档关联，不能直接用于编辑画布。不要反复导入整张图代替修改，导入会追加并产生副本。只有从 Markdown 恢复尚未出现在画布上的图时才使用导入。
4. 每次完整调整使用一个带 `baseRevision` 的事务。遇到版本冲突，重新读取最新内容并重新判断改动，不能只换 revision 后重放旧操作。需要撤销时，用当前 revision 和该次事务 ID 调用 `canvas_undo`；若对象已有后续编辑，不强行覆盖。
5. 创建、删除、连接模块的整次事务及导入完成后自动整理全图；允许移动和调整整个框架的几何，但不改变模块、连接对象、方向或文字。需要单独整理时调用 `canvas_arrange`，使用最新 `baseRevision`，结果可按事务撤销；不用逐个计算和提交坐标。文字编辑和人工拖动不触发整理。判断布局使用结构化几何，不增加截图或图像识别流程。
6. 修改工具只返回 revision、transactionId、changedIds 和草稿状态，不重复返回全图和历史；整理回执和几何上下文附带布局提示，指出相关对象，直线与标签遮挡仅作几何估计。每轮修改前重新读取最新画布；完成后根据回执判断是否成功，只在需要继续读取内容时获取框架。界面的直接关系、上下游及有向路径聚焦是临时查看状态，不改变底图，不表示真实代码影响或测试覆盖。

Canvas 导出包含全部方框描述、连接方向、连线描述和来源，并保留项目 Markdown 中的人工说明。需要保留的“待确认”“设计已确认”“已实现”等状态应写入方框、连线文字或文档说明，不只放在颜色、便签或元数据里；状态必须有用户确认或项目证据支持。决策理由和详细需求仍保留在原有文档中。

模块来源用 `refs` 保存单行文件引用或 HTTP(S) 链接，可通过创建或更新模块的 patch 编辑，也可在界面中编辑。只保存引用，不复制原文；引用存在不表示内容已核验。来源随同一 Markdown 的 `canvas:references` 小节保存和恢复，不手工更换模块标识或把来源仅存在本机草稿。

## 导出与文档入口

**本次 skill 正常结束前必须自动更新项目结构图，无需用户另行要求同步。** 即使本轮只有人工编辑或讨论，也执行收尾保存：

1. 确认本轮浏览器编辑已保存为服务端草稿，调用 `canvas_get_context` 获取最新 revision。
2. 调用 `canvas_save_project`，传入对应 `canvasId` 和 `baseRevision`。工具将最新画布写回登记的项目 Markdown，保留图块前后的人工说明，并回读验证。不要用早先的导出结果或通过 shell 绕过工具覆盖文件。
3. 成功后给出项目结构图路径和同步结果，并按下面规则登记文档入口。

若 revision 过期，重新读取画布再保存；若项目 Markdown 被外部修改、图语法不支持或导出失败，保留现有文件和草稿，明确说明尚未同步及原因，不自动覆盖或丢弃任一方内容。重新打开时，未修改的画布可加载外部更新；存在未同步草稿且文件也变化时需先处理冲突。

`canvas_read_architecture` 用于读取或导出副本，不会写项目文件；界面的「保存到项目」与 `canvas_save_project` 使用同一保存流程。skill 结束后发生的新编辑，在下次调用时同步，不提供后台 Markdown 同步。

成功保存后登记一次读取入口，后续只在路径变更时更新，保留周围已有内容：

- 已有 `docs/agents/domain.md`：登记实际框架图相对链接及下述适用场景，并确保现有项目规则文件有指向该文档的入口。
- 没有 `docs/agents/domain.md`：直接在现有 `AGENTS.md` / `CLAUDE.md` 登记图的链接和适用场景，无需为此运行初始化 skill。优先沿用项目已有约定；两者都存在时不重复写入，两者都不存在时创建 `AGENTS.md`。

登记内容示例（位于 `docs/agents/domain.md` 时）：

> 产品框架图：[architecture.md](../architecture.md)，由 Canvas 导出。分析模块职责、交互关系、核心流程或结构变更时，按需读取此图，并结合相关需求、ADR、代码和测试。它是设计参考，不表示所有内容均已实现。

框架图长期保留，用户可在任何阶段发起调整。后续项目设计按需直接读取完整 Markdown，无需启动 Canvas 或读取本 skill。完整保留模块、关系、描述、状态、约束、待确认事项和来源，不擅自摘要、截断或仅返回局部图；来源原文只在问题需要时展开。读取 Markdown 不构成调用 Canvas skill 的授权。不增加持续检查、固定审查时点或所有 skill 必读要求；设计冲突沿用当前任务的分析与反馈流程，也不因为图与代码不同就自动认定哪一方错误。
