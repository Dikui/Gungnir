# 消融实验

输入：已有收益的完整版本、机制所在的代码或配置、可量化指标和测量命令。

## 开始前

- 读取已有的 `GLOSSARY.md` 和 `docs/adr/` 中的相关 ADR。
- 把 ADR 中记录的决策和理由作为证据。
- 只给诊断结论和建议。
- 不修改项目代码或文档，以下情况除外：只在独立 worktree 中修改代码；主工作区只新增步骤 7 的实验记录。
- 在主工作区运行 `git status --porcelain`。有未提交改动时，提醒用户：实验 worktree 基于 `HEAD` 创建，不包含这些改动；若要测的机制在这些改动中，需要先提交。
- 有未提交改动时，询问用户是否先提交，停下等待回答。用户提交后重新检查再继续；用户选择不提交时，基于当前 `HEAD` 继续，并在实验记录中注明“未包含未提交改动”。代理不自行提交。
- 确认起点后，记录主工作区开始时的 `git status --porcelain` 和 `HEAD` 的 SHA；没有未提交改动时直接继续。
- 用 `git worktree add --detach <仓库外的临时目录> HEAD` 建立实验 worktree，记录其 `HEAD` 为 worktree 基准 SHA。
- 所有实验（开关机制、安装依赖、构建、测量）都在该 worktree 中进行；所有配置在同一 worktree 中测量。
- worktree 缺少依赖或构建产物时，在其中安装或构建；不复制、不修改主工作区的依赖目录。
- 正常结束或提前停止时，均执行步骤 7 的记录与清理。
- 展示或记录命令、输出或环境信息前，将秘密值替换为 `<REDACTED>`。
- 确认有可量化指标和可重复运行的测量命令。缺少时先与用户确定；无法量化时停止，建议用户调用 `/first-principles` 或 `/adversarial-review`。

## 执行规则

- 按顺序执行步骤。
- 完成条件未满足时，不进入下一步。
- 跳过某步时说明理由。
- 需要用户确认时，提出问题。停下等待回答。收到确认前不按假设继续。
- 无法交互时，输出待确认问题和已完成的部分。以 `未完成：等待用户确认` 结束。
- 能从仓库、文档或工具查到的事实，由代理自行查证。
- 决策交由用户确认。
- 证据不足的条目标为 `待确认`。写明缺少的证据。
- 在报告中写明覆盖范围和未覆盖部分。有未覆盖部分时标为 `部分完成`。
- 不得用“未发现问题”代替覆盖说明。不得据此给出整体通过结论。
- 一次只改一个变量；中途不改测量方法；不删除机制，删除建议交给用户。
- 步骤 3 停止或测量中途提前停止时，说明跳过的步骤，仍执行步骤 7 的记录与清理。

## 步骤

### 1. 列机制
列出每个机制的开关方式：配置项、功能开关或可还原的提交回滚。不能独立开关的合为一组并注明。请用户确认机制清单。
仅在实验 worktree 内用提交、`git revert` 等方式开关机制。
完成条件：用户确认了清单；每个机制或机制组都有可执行的开关方式。

### 2. 设计实验
确定指标、方向（越大越好或越小越好）和测量命令。固定数据集、随机种子、环境，以及离散（标准差或极差）和噪声判据。
完整版本 = 全开；基线版本 = 全关。默认每个配置运行 N = 5 次，用户可指定。
完成条件：测量命令已在完整版本上实际运行一次并得到指标值。

### 3. 测噪声
完整版本和基线各运行 N 次，保留原始数据，计算均值和离散。总收益 = 完整均值 − 基线均值。
越小越好的指标，将差值取反后判断收益；记录原始差值和指标方向。后续贡献和交互也沿用此方向与噪声判据。
完成条件：两组数据齐全。按指标方向判断的总收益不超过噪声时停止，结论为“收益不成立”，说明跳过步骤 4–6，并执行步骤 7。

### 4. 留一法
每个配置从完整版本出发，只关一个机制或机制组，运行 N 次。切换前恢复上一个机制，避免累计关闭。
贡献 = 完整均值 − 去掉后均值；按步骤 3 的指标方向解释。
完成条件：每个机制或机制组都有 N 次数据。

### 5. 交互
按同一指标方向，比较各贡献之和与总收益。绝对差距超过噪声时，对可疑组合做加一法（基线上只开一个）或成对实验，每个配置运行 N 次。
建立组合配置时逐个切换开关；对照配置间每次只改变一个机制，固定其他条件。
完成条件：差距在噪声内，或已对可疑组合完成实验，或说明无法解释的残差。

### 6. 判定
每个机制判为必需（去掉后显著下降）、冗余（数据齐全且变化在噪声内）、有害（去掉后显著变好）或无法判定（数据不足或结论不稳定）。判定按指标方向和固定噪声判据进行。
“无法判定”与“冗余”分开写；证据不足的标为 `待确认`，写明缺少的证据。
完成条件：每个机制或机制组都有判定和数据依据，或无法判定的原因。

### 7. 记录并清理
读取同目录 [EXPERIMENT-FORMAT.md](EXPERIMENT-FORMAT.md) 并按其格式写记录。
记录写入用户主工作区，优先沿用仓库已有约定；没有时写入 `docs/experiments/<YYYY-MM-DD>-<name>.md`。写明 worktree 基准 SHA 和是否包含未提交改动。
正常结束或提前停止时，执行 `git worktree remove --force <目录>`，再执行 `git worktree prune`；如在实验中创建过分支，一并删除。
按产出模板报告。提前停止时仍保存已有数据，注明未完成的配置或机制。
完成条件：记录已写入并报告路径；实验 worktree 已删除；主工作区的 `HEAD` 未变，`git status` 除实验记录外与开始时一致。

## 产出模板

对话中的最终产出按 `EXPERIMENT-FORMAT.md` 的“结果”和“结论与建议”两节输出，并附记录路径和覆盖说明。

```
## 结果
总收益：<…>；噪声：<…>
| 机制 | 贡献 | 判定 |

## 结论与建议
<结论与建议；无法判定项及缺少的证据>
记录文件：<路径>
状态：完成 / 部分完成；覆盖范围：<…>；未完成的配置或机制：<…>
```
