# 分流请求

在项目 issue tracker 中分类请求、验证事实并更新处理状态。如果配置将外部 PR 纳入请求入口，也用相同流程处理 PR；下文注明其差别。按 tracker 配置判断 `#42` 等编号指的是 issue 还是 PR。

每条发布到 tracker 的评论或 issue，都必须以以下声明开头：

```
> *This was generated by AI during triage.*
```

参考：[AGENT-BRIEF.md](AGENT-BRIEF.md) 说明任务简报的写法，[OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) 说明 `.out-of-scope/` 拒绝记录库。

## 分类与状态

分类只能有一个：

- `bug`：已有功能出现问题。
- `enhancement`：新功能或改进。

处理状态只能有一个：

| 状态 | 含义 |
| --- | --- |
| `needs-triage` | 等待维护者评估 |
| `needs-info` | 等待报告者补充信息 |
| `ready-for-agent` | 信息完整，可交给代理独立处理 |
| `ready-for-human` | 需要人工实现 |
| `wontfix` | 不处理 |

对于 PR，`ready-for-agent` 表示已附任务简报，代理应继续处理差异；`ready-for-human` 表示可由人合并。

每个已分流请求恰好具有一个分类和一个状态。发现多个状态冲突时，先标明并询问维护者，再做其他操作。

以上是标准角色名，实际标签字符串按项目映射使用。缺少映射时，告知用户先显式运行 `/setup-matt-pocock-skills`。文中其他技能均须用户明确指定后调用，见[调用规则](../../../docs/invocation.md)。

未标记请求通常先进入 `needs-triage`，再转入其他状态。报告者补充信息后，`needs-info` 回到 `needs-triage`。维护者可随时覆盖状态；遇到异常转换，先说明并询问。

## 展示待处理请求

维护者可要求查看待办、处理指定编号或直接改状态。查看待办时，查询三个分组，组内按最旧优先排列：

1. 未标记、尚未分流的请求。
2. `needs-triage` 请求。
3. 最近分流记录后，报告者有新回复的 `needs-info` 请求。

PR 在范围内时，将外部 PR 加入这些分组，并在每行标明 `[PR]` 或 `[issue]`。“外部”按 tracker 配置定义，发现待办时排除协作者正在进行的 PR。维护者明确点名的 PR 不受作者过滤限制。

给出每组数量和每项的一行摘要，让维护者选择。

## 处理指定请求

1. **读取上下文**：完整读取正文、评论、标签、作者和日期；PR 还要读取差异。读取已有分流记录，避免重复提问。按领域词汇查阅代码，遵守相关 ADR。检查请求是否已实现：按领域概念搜索，不只匹配原话，并报告查过哪里。同时读取 `.out-of-scope/*.md`，指出相似的拒绝记录。
2. **提出建议**：向维护者说明建议的分类、状态和理由，并简述相关代码现状，包括是否已实现。等待指示。
3. **验证事实**：在访谈前验证请求。缺陷按报告步骤复现；PR 检出后运行相关测试或命令，确认代码是否做到所声称的行为。报告已确认的结果和代码路径、验证失败或信息不足；信息不足通常应进入 `needs-info`。
4. **必要时访谈**：使用 `/grilling` 和 `/domain-modeling` 补齐请求。决策明确时同步整理领域术语、`GLOSSARY.md` 和 ADR。
5. **应用结果**：按下表处理。

| 结果 | 操作 |
| --- | --- |
| `ready-for-agent` | 按 [AGENT-BRIEF.md](AGENT-BRIEF.md) 发布任务简报评论 |
| `ready-for-human` | 使用同样结构，说明无法委托的原因，如人工判断、外部权限、设计决策或手动测试 |
| `needs-info` | 发布下方的分流记录，明确待补信息 |
| `wontfix`：已实现 | 说明实现位置并关闭，不写入 `.out-of-scope/` |
| `wontfix`：拒绝缺陷请求 | 礼貌解释并关闭 |
| `wontfix`：拒绝改进请求 | 按 [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) 记录理由，在评论中链接，再关闭 |
| `needs-triage` | 应用状态；已有部分进展时可补充评论 |

## 直接改状态

维护者明确要求“将 #42 改为 ready-for-agent”等操作时，说明将修改的标签、评论和关闭操作，然后执行，跳过访谈。未经访谈就转入 `ready-for-agent` 时，询问是否需要撰写任务简报。

## 等待补充信息

```markdown
## Triage Notes

**What we've established so far:**

- point 1
- point 2

**What we still need from you (@reporter):**

- question 1
- question 2
```

将已解决事项全部写入 “established so far”。待答问题要具体、可执行，不能只写“请提供更多信息”。

继续已有会话时，先读分流记录，核对报告者是否回答了待答问题，展示更新后的情况，再继续处理。不要重复询问已解决的问题。
