# 试方案

只有必须在真实代码中才能回答的问题才使用本技能，例如内存布局、内存分配、锁、吞吐、内存占用和真实输入上的行为。其他问题改用：

- 比较接口形态：`/codebase-design` 的 design-it-twice。
- 验证业务逻辑、状态或界面：`/prototype`。
- 方案已选定，判断其中哪个机制带来收益：`/ablation`。

## 开始前

- 读取已有的 `GLOSSARY.md` 和 `docs/adr/` 中的相关 ADR。
- 在主工作区运行 `git status --porcelain`。有未提交改动时，提醒用户：各版 worktree 基于提交创建，不包含这些改动。询问是否先提交，停下等待回答。
- 展示或记录命令、输出或环境信息前，将秘密值替换为 `<REDACTED>`。

## 执行规则

- 按顺序执行步骤。完成条件未满足时，不进入下一步。
- 需要用户确认时，提出问题，停下等待回答。
- 能从仓库、文档或工具查到的事实，由代理自行查证。
- 测量方法确定后，中途不修改。
- 提前停止时，说明跳过的步骤，仍执行第 8 步的清理。

## 步骤

### 1. 写决策草稿

写任何实现之前，与用户确定以下内容：

- 要回答的问题。一次只回答一个问题。
- 两到三个差别明显的方案。
- 量化指标及方向（越大越好或越小越好），以及非量化维度（如可读性、可维护性）。
- 一致性规则：各版输出怎样算一致（逐字节相同、容差内相同、只比较指定字段），以及已知可接受的差异。
- 最小有意义差：小于它的差距不算分出胜负。
- 判定规则：差值的置信区间跨过零或跨过最小有意义差时，性能不参与决策，改按非量化维度决定。

完成条件：用户确认了草稿。

### 2. 冻结比较装置

从当前提交新建分支 `trial/base`，在其中提交各版共用的内容：

- 各方案共同实现的接口。
- 共享测试。测试来自需求，不来自某一版实现。
- 输入语料，其中留一组保留输入，实现期间不提供给各版。
- 构建类型和编译选项。性能比较使用发布构建。
- 测量命令。

记录该提交的 SHA，作为基准 SHA。

完成条件：基准 SHA 已记录；共享测试和测量命令能在基准上运行（尚未实现的部分预期失败）。

### 3. 各版实现

每个方案运行 `git worktree add -b trial/<方案名> <仓库外的临时目录> <基准 SHA>`，派一个子代理在其中实现。各子代理并行工作。任务书只含：该方案的描述、接口、共享测试、允许修改的模块范围和预算。各子代理的预算相同。任务书不含其他方案的代码或进展，也不含保留输入。

不能派子代理时，当前会话依次实现各版，并在记录中写明“各版在同一上下文中实现，可能有锚定偏差”。

完成条件：每版都通过全部共享测试；未通过的方案标为“未完成”，不进入后续比较。

### 4. 对比正确性

把同一批输入（包括保留输入）分别交给各版，按一致性规则比较输出。每条不一致都是候选缺陷，可能在任一版中；逐条判断并记录。有写操作的路径，各版使用各自的进程和数据副本运行。

完成条件：每条不一致都有判断。

### 5. 测量

在同一台机器、同一构建类型下测量：

- 预热次数事先固定，不根据结果调整。
- 正式样本来自多次独立的进程运行。只延长同一进程中的循环不算重复。
- 各版交错运行，减少运行顺序的影响。
- 报告各版指标、差值及其置信区间，以及一个解释差距来源的内部指标（如分配次数、锁等待、缓存未命中）。比较吞吐时，同时报告 CPU 占用。
- 差距接近噪声时，改变链接顺序或内存布局后重测；结论仍不稳定时，写成“无法判定”。
- 记录 CPU 频率设置、绑核、ASLR、编译器版本和内存分配器。

完成条件：每版都有测量数据，并已按第 1 步的判定规则得出量化结论。

### 6. 比较非量化维度

派一个没有参与实现的子代理，只提供第 1 步的决策草稿、各版 diff、测试结果和测量结果。它按每个非量化维度写出各版的优点和代价。一个方案在所有维度上都不优于另一个方案时，直接淘汰。看到结果之后，不新增维度或权重。

完成条件：每个非量化维度都有比较。

### 7. 决策并记录

向用户提交结论和依据，由用户选定方案。

- 用 `/domain-modeling` 把决策写成 ADR：问题、考虑过的方案、数据、未选方案的理由、负面后果。
- 测量的原始数据按 `docs/agents/layout.md` 写入 `docs/experiments/<YYYY-MM-DD>-<name>.md`，写明基准 SHA 和各版提交 SHA。

完成条件：用户已选定方案；ADR 和实验记录已写入。

### 8. 收尾

1. 选定的版本达到入库标准时，合并到当前分支。为赶进度省略了错误处理或边界情况的，在当前分支按共享测试重写。
2. 合并或重写后，使用 `/local-test` 测试并沉淀共享测试。
3. 删除全部临时 worktree 和 `trial/` 分支：`git worktree remove --force <目录>`、`git worktree prune`、`git branch -D <分支>`。未选定的版本不合并。

完成条件：只有选定的版本进入当前分支；临时 worktree 和 `trial/` 分支已删除。
