# 对抗审查

输入：计划、需求文档、设计（文字、文档或 issue），或指定基准之后的代码差异。

## 开始前

- 读取已有的 `GLOSSARY.md` 和 `docs/adr/` 中的相关 ADR。
- 把 ADR 中记录的决策和理由作为证据。
- 只给诊断结论和建议。
- 不修改任何文件。为复现做的临时改动除外。不修复问题。
- 记录开始时的 `git status`，保留已有改动。
- 复现用的临时测试、代码和配置改动带唯一标记 `[ADV-<4 位随机>]`。
- 正常或提前结束前，按本次标记查找并还原全部临时测试和改动，确认 `git status` 与开始时一致。用户要求保留的除外，并在报告中列出。
- 展示或记录命令、输出或环境信息前，将秘密值替换为 `<REDACTED>`。

## 执行规则

- 按顺序执行步骤。
- 完成条件未满足时，不进入下一步。
- 跳过某步时说明理由。
- 需要用户确认时，提出问题。停下等待回答。收到确认前不按假设继续。
- 无法交互时，输出待确认问题和已完成的部分。以 `未完成：等待用户确认` 结束。
- 能从仓库、文档或工具查到的事实，由代理自行查证。
- 决策交由用户确认。
- 证据不足的条目标为 `待确认`。写明缺少的证据。
- 在报告中写明覆盖范围和未覆盖部分。有未覆盖部分时标为 `部分完成`。
- 不得用“未发现问题”代替覆盖说明。不得据此给出整体通过结论。

## 步骤

### 1. 确定主张
代码类分别用 `git rev-parse --verify '<ref>^{commit}'` 解析用户指定的基准和目标（默认 `HEAD`）SHA。
用 `git merge-base <base-sha> <target-sha>` 取共同祖先 SHA，记录这三个 SHA。
后续差异命令和代码读取只用这三个 SHA，不再解析会移动的分支名或 `HEAD`。
SHA 或共同祖先无法解析、命令失败或差异为空时，报告原因并停止。
列出对象声称满足的目标和不变量。优先取自需求文档；没有时从对象中提取。为每条主张编号，请用户确认清单。
完成条件：用户确认了主张清单，每条有编号。

### 2. 攻击
新建不继承当前对话历史的独立攻击方：攻击子代理，或另起一个不带本次对话的 CLI 会话。环境禁用了子代理时，不借用定时任务等无关工具绕过禁用。无法建立隔离上下文时，说明原因并停止。
确保攻击方的结果能回到本会话：前台等待，或使用完成后会自动唤醒本会话的后台机制。
- 给它：审查对象（代码类给固定的三个 SHA 和差异命令）、主张清单、相关文件路径。
- 不给它：作者推理、对话历史、已知风险、上一轮之外的讨论。只读取提供的对象和相关路径；轮间信息仅按步骤 4 提供。
每条反例写明针对的主张、场景或输入、预期与实际、原因及位置、严重度（高/中/低）。
高：阻断核心需求或造成严重数据、安全后果；中：部分需求不满足或影响局部行为；低：影响有限的维护性或规范问题。
要求子代理逐项尝试七项攻击面：边界值与空值、并发与顺序、失败与重试、规模、恶意输入与权限、需求未写明的情况、与现有功能的交互。不设反例数量下限，不凑数。
完成条件：子代理返回反例清单，并逐项说明每个攻击面已尝试或为何不适用。

### 3. 核实
主代理逐条核实。代码类能用失败测试或命令复现就复现，记录命令和输出；不能复现则追踪代码路径。计划类对照事实与约束推理。
完成条件：每条反例都归为成立、驳回（附理由和证据）或待确认（写明缺少的证据）。

### 4. 下一轮
某轮没有新的成立反例，或已满 3 轮，即停止。否则新建攻击子代理，沿用步骤 2 的隔离要求和输入，只额外提供已成立和已驳回清单。只找新反例，再执行步骤 3。
完成条件：每轮反例均已核实；已满足停止条件并记录轮数。

### 5. 报告并清理
按产出模板报告，并按开始前的规则清理。没有成立反例时，在“剩余风险”中写“在已覆盖的攻击面内未发现成立反例”，并列出未覆盖部分。
完成条件：报告包含覆盖说明；`git status` 与开始时一致（用户要求保留的除外）。

## 产出模板

```
## 范围
对象：<…>；固定 SHA：<…>（代码类）；轮数：<n>；状态：完成 / 部分完成

## 成立的反例（按严重度）
### <标题>（高/中/低）
- 主张：#<n>
- 场景：<…>
- 预期 / 实际：<…>
- 原因与位置：<文件:行>
- 复现：<命令与输出，或代码路径追踪>

## 驳回
| 反例 | 驳回理由与证据 |

## 待确认
| 反例 | 缺少的证据 |

## 攻击面覆盖
| 攻击面 | 已尝试 / 不适用（原因） |

## 剩余风险
```
