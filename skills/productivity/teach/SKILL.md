以当前目录保存学习状态，让用户可以跨多次会话学习同一主题。

## 工作区文件

| 位置 | 用途 |
| --- | --- |
| `MISSION.md` | 用户为什么学习。所有教学围绕此目标，格式见 [MISSION-FORMAT.md](./MISSION-FORMAT.md)。 |
| `RESOURCES.md` | 可信资料清单，格式见 [RESOURCES-FORMAT.md](./RESOURCES-FORMAT.md)。 |
| `./learning-records/*.md` | 非显而易见的收获和关键理解，供后续修订和选择教学内容。使用递增编号 `0001-<dash-case-name>.md`，格式见 [LEARNING-RECORD-FORMAT.md](./LEARNING-RECORD-FORMAT.md)。 |
| `./lessons/*.html` | 每课一个独立 HTML 文件，讲清一个与目标相关的小主题。使用递增编号 `0001-<dash-case-name>.html`。 |
| `./reference/*.html` | 从课程提炼、适合快速查阅和打印的参考材料，如速查表、算法、语法、动作和词汇表。 |
| `./assets/*` | 课程共用的样式、测验、模拟器和图表组件，见[共享资源](#共享资源)。 |
| `NOTES.md` | 用户的教学偏好和工作笔记，设计课程前按需回顾。 |

## 先明确学习目标

如果用户不知道目标，或 `MISSION.md` 还没有内容，先询问为什么想学。目标应与实际用途关联，以便选择下一步。

目标可以随着学习改变。先与用户确认，再更新 `MISSION.md`，并增加学习记录解释变化。

## 教学原则

深度学习需要三部分：可信资料提供知识，针对性互动课程训练技能，与真实学习者和实践者交流形成经验判断。不同主题的侧重不同，例如理论物理偏知识，瑜伽偏技能。

`RESOURCES.md` 尚不充分时，先寻找高质量、可信的资料，不只依赖模型已有知识。用它持续记录来源，并为课程中的事实和论断提供外部引用。

区分“现在能轻松回忆”与“长期能记住”。前者可能制造掌握的错觉，教学应以长期保持为目标：

- 通过主动回忆练习提取知识。
- 将练习分散到不同时间。
- 在技能练习中交错相关主题；不将这一方法泛用于知识讲解。

理解新知识时减少无谓难度，避免消耗工作记忆；训练技能时使用适当难度，让用户努力回忆并形成长期记忆。

## 每课如何设计

每课聚焦一个用户能完成的小成果，与学习目标直接相关，篇幅短、完成快。排版和字体应清晰、美观，方便以后复习，可参考 Tufte 的信息设计理念。

用户指定学习内容时围绕其请求展开。未指定时，读取学习记录，结合目标选择最相关、难度刚好的内容，即“最近发展区”：有挑战，但能在帮助下完成。

围绕一项技能组织课程，只讲掌握该技能所需的知识，然后让用户通过互动反馈练习。可以采用测验、轻量浏览器任务，或引导用户完成真实动作，如瑜伽姿势。

每种练习都需要对表现给出反馈，尽可能即时、自动。测验各选项的词数应相同；条件允许时，字符数量也一致，避免排版泄露答案。

每课都要：

- 保存到 `./lessons/`，在可行时通过 CLI 命令为用户打开。
- 用 HTML 锚点链接相关课程和参考资料。
- 推荐一个该主题最优质、最可信的一手来源，供进一步阅读或观看。
- 提醒用户可以继续向代理提问，解决不清楚的地方。

## 共享资源

写课前先读取 `./assets/`，优先复用已有组件。新功能可被后续课程复用时，将其放入 `./assets/` 并引用，不把将来会重复的代码内联到课程里。

共享样式表是工作区的第一个组件，每课都链接它，保持课程外观一致。随着课程增加，再积累测验、模拟器和图表等可复用组件。

## 帮助用户形成实践判断

经验判断来自课堂之外的真实互动。用户提出这类问题时，先尝试回答，再建议可信的学习社区，让其检验所学。社区可以是论坛、subreddit、预算允许的实体课程或本地兴趣小组。

寻找声誉良好的社区；用户不想加入时，尊重其选择。

## 提炼参考资料

创建课程时，同时提炼 `./reference/` 中的参考资料，并从课程链接过去。它们应保留课程精华，便于长期反复查阅，而不是复制整课。

适合提炼的内容包括语法和代码片段、算法和流程图、动作和练习组合，以及领域词汇表。参考页应美观且适合打印。

一旦建立词汇表，所有课程都沿用其中的术语。
