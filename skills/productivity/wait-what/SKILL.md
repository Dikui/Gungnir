# 渐进式解释

帮助用户理解卡住的内容。回顾相关对话，补上缺失的背景、前提或推理，不只缩短上一条消息。无法判断困惑在哪里时，先问一个定位问题。

使用用户的语言，借鉴 ASD-STE100 的简化表达原则：一句话说明一件事，同一概念沿用同一名称，保留必要条件和例外。中文不机械套用英文词数限制。存在 `CONTEXT.md` 时，沿用其中的领域术语。

## 按理解情况升级

默认从简明文字开始。同一问题已按本流程解释过某一级、用户仍没理解时，沿用对话中的进度，针对缺口进入下一级，不重复从头讲。用户明确指定图示、HTML 或视频时，直接使用指定形式。

| 层级 | 解释方式 |
| --- | --- |
| 1. 简明文字 | 先给核心答案，再补必要背景。用一个具体例子解释原因和过程。 |
| 2. 图示 | 用 ASCII 图、流程图或时序图展示关系。沿用同一个例子，标出用户卡住的环节。 |
| 3. 单页 HTML | 将同一问题拆成可逐步展开、回看的说明。每步展示原因和相关状态；需要探索参数时增加交互。优先复用已有且适用的模板或图形组件。 |
| 4. 讲解视频 | 用连续画面和旁白解释同一个过程，突出仍未理解的变化或因果关系。 |

每轮只交付当前需要的一层，留给用户反馈，不提前生成后续层级。用户表示理解，或已能依据解释继续原任务时，停止升级。

## 保持解释可信

- 升级表达形式时，保留同一问题、例子和术语，不靠增加无关内容填满页面。
- 保留事实来源和验证依据。示意数据明确标注，不能充当实际结果。
- 当前环境无法生成目标形式时，说明限制，并提供可交付的替代解释。脚本、分镜或静态页面不能称为已生成的视频。
- 本技能仅由用户明确调用。解释过程中需要其他技能时，也须由用户明确指定，不能自动串联。
