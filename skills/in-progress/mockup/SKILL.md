# HTML 界面设计稿

设计稿长期保留并随需求更新；只想回答一个设计问题、用完就丢时，建议用户改用 `/prototype`。
通过复制 `kit/`、只读索引和目标页面、局部编辑及复用共享样式，减少生成和修改时的 token 消耗。

## 1. 定位与初始化

1. 设计稿默认放在 `design/`；项目 `AGENTS.md` 或 `CLAUDE.md` 有约定时遵循约定，已有设计稿目录则沿用。
2. 已有 `INDEX.md` 时先只读索引，再读本次要改的页面，不扫描其他页面。仅在要改共享变量或样式时读取对应文件。
3. 目录不存在时，执行下列命令。`<skill-dir>` 是本技能目录，`<design-dir>` 是确认后的设计稿目录；复制资源，不重新生成。

   ```sh
   mkdir -p <design-dir>
   cp -R <skill-dir>/kit <design-dir>/kit
   cp <skill-dir>/kit/INDEX.md <design-dir>/INDEX.md
   ```

4. 初始化时，项目已有前端设计变量则只读对应的 CSS 变量、主题文件或 Tailwind 配置，把对应值局部改写进 `kit/tokens.css`，在索引记录来源路径。其余变量保留默认值。
5. 初始化只做一次，不覆盖已有资源。已有目录缺少索引或资源时，只补缺失文件，先把用户指定页面登记进索引，不遍历其他页面。

完成条件：目录和索引可用，设计变量来源已记录。

## 2. 明确需求

缺少页面用途、关键数据或主要操作时，一次性问完，不超过 3 个问题。用户不在时，把假设写入页面开头的交接说明。
完成条件：用途、关键数据和主要操作均有答案或明确标注的假设。

## 3. 新建或修改

- 新页面先执行 `cp <design-dir>/kit/page.html <design-dir>/<page>.html`，再局部修改交接说明和正文。页面放在设计稿目录根部，沿用骨架的相对路径。
- 优先用 `kit/mockup.css` 的语义类；仅需要确认可用组件时读取它。页面专属样式放在页内一个小 `<style>` 块中，颜色沿用变量。
- 列表或表格行用 `data-repeat="N"`，共生成 N 项；用 `data-repeat-index` 标记序号文本。不手写重复行，重复单元内不要放会冲突的 `id`。
- 默认、空数据、加载和出错等状态用 `data-state` 放在同一文件中；无参数时显示 `default`，其他状态通过 `?state=` 打开。
- 弹窗、抽屉或菜单用 `data-toggle="#id"`，目标初始加 `hidden`，目标内的关闭按钮加 `data-close`；按 Esc 也关闭。
  弹窗和抽屉的面板容器（即 `data-toggle` 指向的目标）加 `role="dialog"` 和 `aria-modal="true"`，`mockup.js` 依赖此标记实现焦点锁定。
- 标签容器加 `data-tabs`；每个按钮加 `data-tab`，每个面板加 `data-panel`，两者各自按顺序对应。每个容器的按钮数与面板数必须一致。
- 使用原生表单组件，交互由 `kit/mockup.js` 提供。不写页面脚本，不引入外部框架或 CDN；数据和保存结果仅作标明的演示。
- 修改时用编辑工具局部替换，不整页重写。多页共用的调整改 `kit/tokens.css` 或 `kit/mockup.css`，不要逐页修改。
- 仅在用户要求比较时，同文件用 `data-variant` 放 2 到 3 个结构不同的方案，通过 `?variant=` 或底栏逐个比较。无参数时显示第一个方案，← → 也可切换。
- 用户选定后删掉落选方案，在索引变更记录写明选择和理由。

完成条件：主要操作、所需状态及方案都能由数据属性和 URL 参数展示，交接说明区分已确定内容与占位。

## 4. 展示真实效果

布局、视觉层级、间距和响应式必须能直接作为开发参照。业务内容简短且可信；没有真实数据时明确标注占位，不编造统计数字、用户评价或品牌信息。插图用带文字标签的 `.placeholder`。

避免以下做法：

- 大面积紫粉渐变。
- emoji 装饰。
- 无来源的数字统计区。
- 三列同质的功能卡片。
- 到处都是的左边框色卡片。
- 用 SVG 手绘人物插图。

## 5. 检查与交接

截图前如果切换栏挡住了要看的内容，可以加 `?bar=0` 将它折叠。

1. 有浏览器工具时，打开每个改动页面，检查所需状态、方案和主要交互，确认控制台无报错，每页截一张缩小的截图。响应式相关的改动，再用 `?frame=mobile` 截一张。
2. 最多两轮“修改加截图”。仍有问题时记录具体问题交接；没有浏览器工具时告诉用户双击 HTML 文件打开，不声称完成视觉检查。
3. 更新页面交接说明的“更新”行；在 `INDEX.md` 变更记录追加一行，页面状态变化时同步更新页面表。
4. 回复只给文件路径、打开方式、可用的 `?state=` 和 `?variant=` 值，以及不超过 3 行的改动说明，不复述页面内容。

完成条件：检查结果或未检查范围已交代，交接说明与索引同步，文件可直接打开并继续局部维护。
